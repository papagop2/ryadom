# Развёртывание «Рядом» на ПК №2

## Факт

Стенд развёрнут на `WIN-KOIKRJSNRTL` (Windows 11, `192.168.50.150`):

- `LocalAppServer` на `http://192.168.50.150:8080/` не изменялся и остаётся точкой отката.
- PostgreSQL 16.16 — нативная служба `postgresql-x64-16`, слушает только `127.0.0.1:5432`.
- Роли: `rjadom_migrator` (владелец схемы) и `rjadom_app` (только DML). База `rjadom`.
- API и статика: `api/host.mjs` (Fastify) на `https://192.168.50.150:443`.
- Служба WinSW `rjadom-host` под `NT AUTHORITY\LocalService`, запускается без входа пользователя.
- Сертификат: self-signed, SAN `app.home.arpa`, `192-168-50-150.sslip.io`, `WIN-KOIKRJSNRTL`, `localhost`, IP `192.168.50.150`/`127.0.0.1`; действует 3 года.
- Брандмауэр: входящий TCP 443 разрешён только из `192.168.50.0/24` (правило «Rjadom HTTPS LAN»).
- Секреты, PFX, публичный `.cer` и дампы: `C:\Users\User\Desktop\netral2\secrets` и `backups`, вне репозитория.

Почему не IIS: на этом ПК нет URL Rewrite и ARR, порт 443 свободен. План допускает резервный вариант — один Node-сайт, раздающий PWA и API на одном origin. TLS завершается в Node, порт API `3100` наружу не публикуется.

## Сборка и обновление

1. Зависимости лежат в `node_modules` (перенесены готовыми), реестр npm с ПК №2 отвечает `ECONNRESET`. `npm ci` здесь не запускать; новые пакеты переносить вместе с `package-lock.json`, не отключая проверку TLS и целостности.
2. Из `C:\Users\User\Desktop\netral2\superapp-pc2`: `npm.cmd run build`, `npm.cmd test`, `node tests/smoke.mjs`. Smoke занимает loopback-порты `3100` и `4173`; служба стенда слушает `443`, конфликта нет.
3. Миграции — ролью `rjadom_migrator`, сид — ролью `rjadom_app`; значения брать из `netral2\secrets\rjadom.env`. Повторный сид не дублирует каталог.
4. Обновление стенда: собрать `dist`, остановить `rjadom-host`, применить обратно совместимые миграции, запустить службу, проверить `/api/health/live` и `/api/health/ready`. При сбое вернуть предыдущий `dist` и перезапустить службу. После изменения API службу обязательно перезапустить: процесс держит маршруты в памяти. На 19.11.2026 применены миграции `0001`–`0006` (модерация, кабинет партнёра, уведомления, поездки, заявки на выезд, товары и самовывоз, зоны и курьерская доставка), readiness отдаёт `migrations: 6`.
5. Карта: PWA грузит тайлы `tile.openstreetmap.org`. Это допустимо для стенда и демо, но для публичного запуска нужен провайдер с проверенными лимитами и условиями хранения (см. `PLAN.md`); серверные ключи карты не класть в PWA.

## Сертификат и телефон

1. Публичный сертификат: `netral2\secrets\rjadom-tls.cer`. Приватный ключ (`rjadom-tls.pfx`) с ПК не копировать.
2. На проверенном Samsung SM-A920F (Android 10) штатная установка CA недоступна: «Установить из памяти» и «Установка сетевых сертификатов» требуют закрытый ключ. Нужно другое устройство/прошивка с пунктом «CA certificate» либо сертификат публичного CA.
3. Адрес: `https://192-168-50-150.sslip.io/` (публичный DNS уже указывает на `192.168.50.150`); `https://app.home.arpa/` — при наличии локального DNS. Не отключать проверку сертификата.
4. Если Wi-Fi изолирует клиентов (TCP до ПК и роутера с телефона не проходит, хотя ping идёт), для проверки использовать `adb reverse tcp:8443 tcp:8443` и `http://localhost:8443` — localhost считается secure context, service worker и установка PWA работают. Для реальной LAN-проверки нужна сеть без AP isolation.
5. На ПК брандмауэр управляется политикой; локальные правила для `node.exe` могут блокировать вход. Проверить `deploy/fix-firewall.ps1` (отключает блокирующие правила Node.js и включает «Rjadom HTTPS LAN»).

## Служба и журналы

- Управление: `netral2\service\rjadom-host.exe status|restart|stop|uninstall` либо `Restart-Service rjadom-host` от администратора.
- Конфигурация службы: `netral2\service\rjadom-host.xml` (переменные окружения внутри, каталог доступен только администраторам и `LocalService`).
- Журналы: `netral2\logs\rjadom-host.out.log`, `rjadom-host.err.log`, `rjadom-host.wrapper.log`; ротация по 10 МиБ.
- Повторная установка: `deploy/install-service.ps1` от администратора (копирует WinSW, пишет XML, выдаёт ACL, ставит правило брандмауэра).

## Бэкап и восстановление

- Дамп: `pg_dump -Fc` ролью приложения или мигратора в `netral2\backups`.
- Проверка восстановления: `pg_restore` в отдельную БД, сверка количества строк, затем удаление тестовой БД.
- Проверено 19.11.2026: дамп `rjadom-20261119-030457.dump` восстановлен в `rjadom_restore_test` — 6 заведений, 8 услуг, 16 записей, 1 миграция.
- Осталось: ежедневное расписание дампа и копия на другой носитель или ПК; ориентиры RPO 24 ч, RTO 4 ч.
