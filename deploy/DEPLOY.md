# Развёртывание «Рядом» на ПК №2

## Факт

Стенд развёрнут на `WIN-KOIKRJSNRTL` (Windows 11, `192.168.50.150`):

- `LocalAppServer` на `http://192.168.50.150:8080/` не изменялся и остаётся точкой отката.
- PostgreSQL 16.16 — нативная служба `postgresql-x64-16`, слушает только `127.0.0.1:5432`.
- Роли: `rjadom_migrator` (владелец схемы) и `rjadom_app` (только DML). База `rjadom`.
- API и статика: `api/host.mjs` (Fastify) на `https://192.168.50.150:443`.
- Служба WinSW `rjadom-host` под `NT AUTHORITY\LocalService`, запускается без входа пользователя.
- Сертификат: self-signed, SAN `app.home.arpa`, `192-168-50-150.sslip.io`, `WIN-KOIKRJSNRTL`, `localhost`, IP `192.168.50.150`/`127.0.0.1`; действует 3 года.
- Брандмауэр: входящий TCP 443 разрешён только из `192.168.50.0/24` (правило «Rjadom HTTPS LAN»).
- Секреты, PFX, публичный `.cer` и дампы: `C:\Users\User\Desktop\netral2\secrets` и `backups`, вне репозитория.

Почему не IIS: на этом ПК нет URL Rewrite и ARR, порт 443 свободен. План допускает резервный вариант — один Node-сайт, раздающий PWA и API на одном origin. TLS завершается в Node, порт API `3100` наружу не публикуется.

## Сборка и обновление

1. Зависимости лежат в `node_modules` (перенесены готовыми), реестр npm с ПК №2 отвечает `ECONNRESET`. `npm ci` здесь не запускать; новые пакеты переносить вместе с `package-lock.json`, не отключая проверку TLS и целостности.
2. Из `C:\Users\User\Desktop\netral2\superapp-pc2`: `npm.cmd run build`, `npm.cmd test`, `node tests/smoke.mjs`. Smoke занимает loopback-порты `3100` и `4173`; служба стенда слушает `443`, конфликта нет.
3. Миграции — ролью `rjadom_migrator`, сид — ролью `rjadom_app`; значения брать из `netral2\secrets\rjadom.env`. Повторный сид не дублирует каталог.
**Web Push.** Для push нужны три переменные окружения службы: `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY` (base64 PKCS#8 DER) и `VAPID_SUBJECT` (`mailto:`). Ключи генерируются `node deploy/make-vapid.mjs`, хранятся в `secrets/rjadom-host.env` и `service/rjadom-host.xml`, не в репозитории. Без них API отвечает `enabled:false`, кнопка в профиле остаётся выключенной; остальное приложение работает. Push требует HTTPS с доверенным сертификатом и разрешения браузера; на iPhone — установка PWA и поддерживаемая версия iOS.

4. Обновление стенда: собрать `dist`, остановить `rjadom-host`, применить обратно совместимые миграции, запустить службу, проверить `/api/health/live` и `/api/health/ready`. При сбое вернуть предыдущий `dist` и перезапустить службу. После изменения API службу обязательно перезапустить: процесс держит маршруты в памяти. На 21.11.2026 применены миграции `0001`–`0022` (модерация, кабинет партнёра, уведомления, поездки, заявки на выезд, товары и самовывоз, зоны и курьерская доставка, города/источники/внешние отзывы, скрытие демо-города, обложки и фотолента, договорные предложения водителей, детали поездки, адреса точек маршрута, двойное подтверждение наличных по заказам/заявкам и записям, живые очереди, избранное, Web Push, штампы лояльности, часы работы и «открыто сейчас»), readiness отдаёт `migrations: 22`.
5. Каталог пилотного района: снимок `db/data/slyudyanka-2gis.json` импортируется идемпотентно командой `node db/import-2gis.mjs` (**518 организаций**, **7 845** публичных отзывов, **8 737** фото: Слюдянка, Байкальск, Култук, Утулик, Порт Байкал, Новоснежная, Мурино). Дополнительный слой `db/data/slyudyansky-osm.json` — **362 организации** OpenStreetMap (ODbL) — импортируется `node db/import-osm.mjs`; он не удаляет карточки 2ГИС и обновляется по `source_id=osm:<type>/<id>`. Категории сводятся общим классификатором `db/categories.mjs` по рубрикам/тегам: автосервисы и шиномонтаж — «Сервисы», салоны — «Красота», аптеки и клиники — «Здоровье», кафе и продуктовые магазины — «Еда»; гостиницы и кемпинги — «Сервисы». После правки классификатора повторный импорт обновляет категории. Новый город: `node db/import-2gis.mjs --city=<slug> --name=<имя> --region=<регион> --lat=<широта> --lng=<долгота> --file=db/data/<файл>.json`. В интерфейсе источники «2ГИС» и «OpenStreetMap» подписаны и ведут на исходную карточку/полную ленту отзывов; свои отзывы хранятся отдельно и проходят модерацию. Снимки статические и не являются официальным API 2ГИС; перед публичным запуском проверить условия использования/перейти на официальный API и сохранить атрибуцию ODbL.
6. Карта и адреса: PWA грузит тайлы `tile.openstreetmap.org`; для каждого города используются его координаты, такси стартует из центра выбранного города. Карта каталога запрашивает `GET /api/v1/places/map?city=<slug>` и показывает **весь** каталог (кластеры при отдалении, отдельные пины при приближении), а не только первые 50 из списка. Геолокация браузера включается кнопкой «Где я», маршрут из карточки открывает Яндекс Карты от текущего места, фотолента — на 2ГИС. Такси запрашивает дорожный маршрут у публичного OSRM (`router.project-osrm.org`, резерв `routing.openstreetmap.de`, переопределение `OSRM_URL`) на сервере и отдельно в PWA для геометрии; при недоступности остаётся прямая оценка. Подсказки адресов и обратный геокодер идут через `GET /api/v1/geo/search` и `/geo/reverse` (по умолчанию Nominatim, переопределение `GEOCODER_URL`); сервер ограничивает частоту и кэширует ответы. Адрес сохраняется в `from_address`/`to_address` и в заездах, поэтому после перезагрузки остаётся не только точка, но и адрес. Публичные Nominatim/OSM-тайлы/OSRM допустимы только для стенда и закрытого пилота: перед публичным запуском нужны свои или договорные геокодер, тайлы и маршрутизатор с проверенными лимитами, SLA и политикой хранения (см. `PLAN.md`). Серверные ключи карты не класть в PWA.

## Сертификат и телефон

1. Публичный сертификат: `netral2\secrets\rjadom-tls.cer`. Приватный ключ (`rjadom-tls.pfx`) с ПК не копировать.
2. На проверенном Samsung SM-A920F (Android 10) штатная установка CA недоступна: «Установить из памяти» и «Установка сетевых сертификатов» требуют закрытый ключ. Нужно другое устройство/прошивка с пунктом «CA certificate» либо сертификат публичного CA.
3. Адрес: `https://192-168-50-150.sslip.io/` (публичный DNS уже указывает на `192.168.50.150`); `https://app.home.arpa/` — при наличии локального DNS. Не отключать проверку сертификата.
4. Если Wi-Fi изолирует клиентов (TCP до ПК и роутера с телефона не проходит, хотя ping идёт), для проверки использовать `adb reverse tcp:8443 tcp:8443` и `http://localhost:8443` — localhost считается secure context, service worker и установка PWA работают. Для реальной LAN-проверки нужна сеть без AP isolation.
5. На ПК брандмауэр управляется политикой; локальные правила для `node.exe` могут блокировать вход. Проверить `deploy/fix-firewall.ps1` (отключает блокирующие правила Node.js и включает «Rjadom HTTPS LAN»).

## Служба и журналы

- Управление: `netral2\service\rjadom-host.exe status|restart|stop|uninstall` либо `Restart-Service rjadom-host` от администратора.
- Конфигурация службы: `netral2\service\rjadom-host.xml` (переменные окружения внутри, каталог доступен только администраторам и `LocalService`).
- Журналы: `netral2\logs\rjadom-host.out.log`, `rjadom-host.err.log`, `rjadom-host.wrapper.log`; ротация по 10 МиБ.
- Повторная установка: `deploy/install-service.ps1` от администратора (копирует WinSW, пишет XML, выдаёт ACL, ставит правило брандмауэра).

## Бэкап и восстановление

- Дамп: `deploy/backup.ps1` ролью мигратора из `secrets/rjadom.env`; пишет `pg_dump -Fc` в `netral2/backups`, проверяет файл через `pg_restore --list`, считает SHA-256 и удаляет дампы старше 30 дней. Пароль берётся из окружения, в командную строку и репозиторий не попадает.
- Расписание: `deploy/install-backup-task.ps1` создаёт задачу `RjadomBackup` на 03:30 ежедневно; `-Time`, `-TaskName`, `-KeepDays` можно переопределить. Задача зарегистрирована как интерактивная для текущего пользователя (без сохранения пароля); после перезагрузки ПК должна быть активна сессия пользователя. Проверено: ручной запуск и `Start-ScheduledTask` завершаются с кодом 0, дамп создаётся.
- Внешняя копия: передайте `-MirrorDir=<путь>` в `backup.ps1` или задайте `RJADOM_BACKUP_MIRROR`; скрипт копирует дамп и `.sha256`, сверяет хеш и хранит копию отдельно. На 21.11.2026 второй носитель/сетевое хранилище не подключены, поэтому фактическая внешняя копия ещё не настроена; локальный дамп и расписание работают. Для публичного запуска без внешней копии не обходиться.
- Проверка восстановления: `pg_restore` в отдельную БД, сверка количества строк, затем удаление тестовой БД. Проверено 21.11.2026 на `rjadom-20261121-030056.dump`: восстановлено 886 заведений, 14 миграций, 19 записей; тестовая БД удалена.
